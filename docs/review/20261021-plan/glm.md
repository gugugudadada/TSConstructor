# 最终版提示词
# TSConstructor2 · P1+P2 开发任务：结构感知编辑与跨样本迁移
## 0. 任务目标与定位
在现有 TSConstructor2 项目上增量开发两件事：
- **P1 结构识别与定位**：自动检测波形中可编辑的几何结构(平台/峰谷/斜坡)，用户可直接选择结构作为编辑目标，而不必总是手工划定坐标区间。
- **P2 结构锚定与跨样本迁移**：配方步骤可绑定到**结构描述**而非绝对坐标；换基源批量生成时，系统在每个基源上重新检测并匹配结构，将同一编辑意图应用于匹配到的结构。
**为什么这是核心机制而不是功能装饰**：本系统的主打场景是**缺类重建**——目标类别在可用数据中没有(或极少)真实样本，用户从其他类样本出发构造目标类。这个场景下，编辑意图必须能跨基源复用：用户在一条基源上“缩短尾部平台”，换到下一条基源时平台位置不同，纯坐标配方会编辑到错误位置。结构锚定解决的就是这个问题。当前泛化控制的“锚点漂移/宽度缩放”轴是纯坐标随机偏移，无法保证语义一致——这是本任务要补的真实缺口。
**数据集口径**：本轮以 Wafer 为机制验证场(数据、1NN 脚本、走查均在仓库内)；结构引擎保持通用，不得把检测定义硬编码到某条 Wafer 样本。数据集切换机制已存在，ECG 等其他数据集接入不在本轮。
**核心约束一句话**：结构锚定只回答“**操作对象在哪**”，不回答“改成什么样”(仍是算子参数)、“为什么改”(仍是用户意图)、“好不好”(仍是第二阶段裁决)。

## 2. P1:结构识别引擎
新增 `src/engine/structures.js`(如匹配器复杂可加 `structureMatching.js`),不引入大型信号处理框架。
**纯函数契约**:`detectStructures(values, config) -> StructureDetectionResult`。同输入同配置同结果；**无 RNG**;不依赖 UI 状态。
**归一化口径(写死)**：所有高度/电平/显著性归一化单位 = **基源原始标准差 σ**(即 `recipe.js` 中组件形状的 stdBase 同一口径)。禁止裸原始数值阈值跨数据集通用。
### 2.1 结构实例契约
每实例至少含:`id`(当前波形版本内稳定)、`type`、`startIndex/endIndex`(闭区间)、`centerIndex`、`relativePosition`([0,1])、`width`/`normalizedWidth`、`height|level`(σ 口径)、`prominence`(适用时,σ 口径;不适用显式标记不伪造)、`properties`(类型特有属性)。索引边界、空集语义、口径在代码注释说明。**实例 ID 不是跨样本身份**——跨样本匹配只依据结构描述与测量特征。
### 2.2 三种检测器(首版只做三类)
1. **平台 plateau**:允许波动的平缓区域；局部斜率/区间波动准则；相邻短间隙合并；最小长度过滤；输出边界/中心/宽度/代表电平。
2. **峰/谷 peak|valley**:局部极值+最小间距+显著性；处理平顶峰、端点、重复值；重叠实例确定性去重；输出中心/幅度/显著性/邻域边界。
3. **斜坡 ramp**:持续单调区间(允许小幅回折)；斜率+持续长度条件；区分持续斜坡与单点跳变；输出边界/方向/拟合斜率/总变化/宽度。
不得把几何结构自动标注领域语义(不叫“故障平台”、不判医学成分)。
### 2.3 检测配置
- 默认值合理且有限；界面只暴露 2–3 个直观敏感性设置，细节阈值进折叠高级区；
- 检测配置**集中管理**(store 单一来源)，画布/列表/生成引擎不得各持默认；
- 静默改阈值禁止；配置变更须可见。
## 3. P1 界面
**画布叠加**(EditCanvas,可开关)：结构标记与现有图层共存——基源灰线、中间橙渐淡、最终粗线、拖拽虚线预览、失败步灰虚线、克隆落点蓝带。平台/斜坡用区间标记，峰/谷用点位标记；选中高亮；按类型过滤；不遮挡波形；显示当前检测配置状态。
**结构列表**：紧凑列表按类型分组(如“平台 1:位置 0.18,宽度 14,电平 −0.7σ”);点击列表项 ↔ 点击画布标记双向同步：高亮波形、显示属性、设为当前结构对象。检测结果为空显示明确空状态。
**选区关系**：结构锚定是**第三种作用域模式**(绝对选区/结构锚定并存)，不占选区名额；界面须清晰区分“当前选中的是手工选区还是检测结构”。
P1 不要求自动编辑结构，但选择结果必须可被 P2 绑定——不做只能看不能用的展示模块。
## 4. P2:结构锚定
### 4.1 配方扩展
现有步骤参数字段(`anchor/width/span/dstStart` 等)全部保留；为步骤增加可选 `target` 字段：
```
target: {
  mode: "absolute"            // 缺省,沿用现坐标语义
  | "structure",
  descriptor: {               // 结构描述(绑定时刻保存为独立数据)
    type, relativePosition, normalizedWidth,
    relativeLevel, prominence, direction,   // 按类型取适用子集
    context                    // 可选:邻接结构/局部趋势
  },
  location: "start|center|end",
  offset: 0                    // 相对结构位置的附加偏移(点)
}
```
- 旧配方无 `target` → 自动沿用绝对坐标语义，行为不变；
- `mode:"structure"` 且匹配失败 → **该步失败**：沿用现有“保留前值、记录原因、继续执行后续步骤”语义，UI 用失败步灰虚线+title 显示原因；
- **禁止静默回退绝对坐标**；导出保留锚点定义、匹配结果与实际执行位置。
### 4.2 锚点属性
定位依据 = 属性向量，**不得只用“第 k 个平台”**(序数不可靠)：type/relativePosition/normalizedWidth/relativeLevel/prominence/direction/context,按结构类型取适用子集(不用峰的显著性评平台)。允许“某区域内第 k 个”作为辅助描述，不能替代其他特征。属性相似导致歧义时**必须显示歧义、交人工确认**，不得擅自选择。
### 4.3 匹配器
`matchStructure(descriptor, detectedStructures, config) -> MatchResult`:
- 纯函数、同输入同结果；只匹配兼容类型(或显式映射)；
- 综合位置/宽度/相对电平/方向/上下文，**统一特征尺度**(σ 口径，避免大数值特征主导)；
- 明确阈值与拒绝规则；区分四种结果：唯一命中/歧义(多候选)/无候选/检测失败；记录命中实例、得分、未匹配原因；
- 匹配分只是结构相似度，**不得显示为类别正确率或质量分**。
### 4.4 失败显式五类
无候选 / 多候选歧义 / 结构长度不满足操作要求 / 参数在当前结构上不可执行 / 基源与描述差异过大。各给明确 UI 提示与出路(重选锚点/调描述/排除该基源/换绝对坐标)。
### 4.5 操作绑定范围
以下现有步骤支持结构锚定(**复用现有执行函数**,不另写引擎):
- `warp` / `erase` / `scale`:锚定解析产出执行区间；
- `component` 与 `deform`:锚点解析为结构上 `location+offset` 位置；
- **`transplant` 落点锚定(旗舰演示)**：片段落点绑定到结构(如“移植到尾部平台中心”)——这是本系统最强表达工具与新机制的组合，作为验收演示之一。
**执行语义(点破)**：结构解析的产物就是一个 span/anchor 数值——解析完成后**进入既有执行路径**(含 vary 漂移轴作用于解析后位置)，不新增执行分支。
手工自由编辑完整保留；不强制一切经结构检测。
### 4.6 跨基源迁移执行契约(v1 确定性语义)
1. 用户在源样本上检测→选结构→绑定步骤(保存描述);
2. 批量生成勾选多基源；
3. **对每个基源的原始波形执行一次检测**(缓存键=基源 ID+波形版本+检测配置);
4. 锚点描述与该基源结构实例匹配，**在配方执行前解析出实际区间**；
5. 配方按既有顺序执行(后步以前步输出为输入，锚定参考仍为原始基源结构位置，不做动态重检测);
6. 候选保存实际匹配结果；成功/失败分别可见。
原始基源缺目标结构 → 该基源上此步失败(可见)，其余步骤照常，候选报告失败步骤，不隐藏。
**本轮不做**：锚点间依赖、循环引用、执行结果语义重解释、自动组合为新类别、从波形推断类别。
## 5. 匹配预览与候选可见性
**生成前·匹配预览**(紧凑，不建大工作区)：显示各基源匹配状态、逐个查看命中结构与属性对比(源锚点 vs 目标实例)、可确认/调描述/排除基源；失败与歧义可见；**不得自动改源数据或配方**。交互范式建议参考 SourceCorner 角窗模式或紧凑列表，自行判断落位。
**生成后·CandidateViewer 集成**：查看器已存在(批次下拉/列表/基源-候选对照/差异签名)，在其详情中**补**：该候选各结构锚定步的命中结构标记(叠加在波形对照上)、锚定状态(命中/歧义/失败)与属性对比。不新建画廊，不做评分/裁决/归档。
## 6. 差异签名与候选记录
每候选保留：基源 ID、配方定义、锚点定义、命中实例及原始位置、解析出的实际区间、实际参数、seed、逐步成功/失败状态、既有 tags。
结构锚定新增 tag 约定:`锚=结构(平台#2)`、`锚解析108-126`、`锚失败`、`锚歧义`;`axisCounts` 补充锚定命中/歧义/失败计数。绝对坐标步骤 tags 照旧。
**两条禁止解读**：“匹配到了结构”≠“候选质量更好”；锚定不保证同基源批量候选多样性——若变化仍小，如实说明，不在本轮解决。
## 7. 可复现性与兼容
- 同基源+同配方+同检测配置+同设置 → 确定性匹配与候选；检测/匹配无随机性；随机仍走现有种子链；
- **不得因匹配失败暗中换候选或换坐标**；
- 导出 schema **纯增量**(target 可选字段)；无持久化/导入，旧导出文件继续被 `wafer-1nn.mjs` 消费(steps 新字段被忽略即可)，验证一次；
- 检测缓存不得改变结果，只优化性能。
## 8. 测试
**检测器单测**(平台/峰谷/斜坡各 ≥6 例)：理想结构/加噪/边界/相邻两例/低于阈值/空输入与常量波形；验证起止、索引合法、去重、空集语义。
**匹配单测**(≥10 例)：自身匹配/位置偏移后命中/宽度变化后命中/多相似结构显歧义/无结构显失败/结果与调用顺序无关/执行区间与画布标记一致/旧坐标配方不变/同 seed 复现/失败原因可从导出中找到。
**真实 Wafer 走查**(8–12 条形态各异的样本，含清晰平台/弱平台/多峰谷/与锚点源差异大者；**至少一次完整缺类重建场景**：新建目标类→多基源→锚定配方→生成→查看器核对)。**必报读数**：“N/12 基源无需人工调整描述即匹配成功”+全部失败/歧义案例清单+是否需调描述。
## 9. 验收标准
**P1**:三检测器独立可测；叠加开关/类型过滤/双向选择可用；属性可查；选中结构可绑定为目标；配置一致(切换不显示旧结果)；空状态明确。
**P2**:warp/scale/component/deform/**transplant 落点**均可锚定；锚点=结构描述非坐标；跨基源重检测重匹配；匹配预览可见命中与失败；无匹配不静默退化；手工编辑与旧配方不变；候选追溯含锚定信息；CandidateViewer 显示匹配标记；单测+回归+走查全过；**旗舰演示(移植到结构)走查记录在案**。
**交付**：可运行代码、文件清单、设计说明、测试结果、走查结果(含量化读数)、已知限制、明确说明本轮**未**解决的多样性问题。
**执行顺序**：① 查仓库确认基线 → ② 记录现有步骤真实数据结构与执行语义 → ③ structures.js+单测 → ④ 叠加层+结构列表 → ⑤ 配方 target 扩展 → ⑥ 匹配器+匹配预览 → ⑦ 解析接入既有执行路径 → ⑧ CandidateViewer 补标记 → ⑨ 测试+走查 → ⑩ 更新 `docs/current-system-guide.md`。次要细节可保守决策并记录假设；数据结构无法支持某功能时先查现有执行路径取最小改动，**禁止绕开既有引擎另写一套**。若中途体量超限，优先保证 P1 完整交付，P2 可截断但须附明确交接说明。
## 10. 结尾三问(走查后如实回答)
1. **结构锚定是否比固定坐标更适合跨样本迁移？** 用实际样本与匹配数据说明，不许凭设计推断；
2. **哪些情况会匹配失败或匹配错误？** 列全失败案例；
3. **是否真正减少了手工定位？** 未做用户实验前，只能依据走查判断，**不得宣称已证明用户效率提升**。
本轮目标是验证结构感知编辑的有效性，不是把系统做大。宁可交付少量可靠、可解释、可复现的结构匹配，不要大量无法稳定迁移的检测器与按钮。
