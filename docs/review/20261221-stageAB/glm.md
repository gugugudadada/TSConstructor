## 〇 · 总判
评估文档的裁决(“GLM 立项、GPT 补验收”)成立，阶段 A/B 的执行质量高于任务书要求——尤其是**适配层路线**(复用现有引擎而非重写)是对的方向，而且它纠正了包括我在内的一个共同错误：我下发的任务书写的是“新增 `src/engine/structures.js`”,而该文件连同六个检测器、`detectAll()`、`structureFingerprint()` 早已存在。评估文档抓住这一点并改为“适配层”方案，是本轮最有价值的一个修正——否则会造出两套检测口径，污染已有的结构指纹。阶段 A 的“不影响 fingerprint 口径”隔离声明处理得干净。

## 二 · 阶段 C 开工前必须钉死的 6 个设计决策
评估文档的阶段 C 只列了功能清单，以下 6 个决策点它没有覆盖——不先钉死，agent 会自行发明语义，而每一处都踩在行为敏感区：
| # | 决策 | 裁定 | 理由 |
|---|---|---|---|
| **D1** | **transplant 锚定解析什么** | v1 **只解析 dstStart(位置)**，dstSpan 长度保持现行为(绑定时选区长度/默认落点长度) | 最小侵入 + “解析产物进既有路径”原则。“落点长度随匹配结构宽度”(基源 A 平台 20 点、基源 B 14 点时落点跟着变)是语义上更一致的选择，但改变行为——登记为后续选项，不进 v1。**这是旗舰演示的行为定义，不钉死必出分歧** |
| **D2** | **匹配用哪份检测配置** | 生成时刻的当前 `structureConfig`(灵敏度)；绑定时保存的 descriptor 是独立数据，不受灵敏度变化影响 | 契约写明：改灵敏度 = 改设置 = 可能改变匹配结果(可复现性口径内)；descriptor 是属性向量，跨配置仍有语义 |
| **D3** | **匹配器特征权重** | 各特征已 σ/长度归一但自然量程不同(relativePosition ∈[0,1] vs prominence 可达 3σ+)——定义每特征归一或显式权重；阈值进 config 非魔法数；**歧义判定 = 前二得分差 < 裕量**，报告两个候选 | 否则某个量程大的特征会主导匹配；歧义显式是任务书硬要求 |
| **D4** | **tags 归 C 不归 D** | `锚=结构(平台#2)` / `锚解析108-126` / `锚失败` / `锚歧义` + axisCounts 锚定命中/歧义/失败计数，**随 C 交付**；导出含 target/命中实例/实际区间也在 C | 匹配预览排在 D,若 tags 也推到 D,整个阶段 C 的跨基源生成就是黑箱——tags 是 C 期间唯一的逐候选可见性，成本极低。D 的 CandidateViewer 标记只是把 tags UI 化 |
| **D5** | **vary 位漂移的作用点** | 漂移作用于**解析后的位置**(resolved span/anchor/dstStart 之后)，即现有 drift 语义零改动；明写“禁止为锚定发明新漂移语义” | 与“解析产物进既有路径”同一条原则的推论；不写明 agent 可能把漂移做在解析前(那样会漂走结构) |
| **D6** | **失败传播口径** | 匹配失败 = **步级失败**(保留前值+记录原因+继续执行+候选照产+失败标记)，不是候选级拒绝、不是整批拒绝；批量汇总中失败计数可见 | 与现有“能算就产出、失败步带原因”完全一致；评估文档对 GPT 措辞的纠正(“不能视为正常产物”→“带失败标记产出”)正是这个口径，C 的实现必须落在同一口径上 |
## 三 · 阶段 C 验收的补充条款(在评估文档清单之上)
1. **旗舰演示走查记录在案**：绑定 transplant 落点到结构 → ≥3 基源批量生成 → 每基源解析位置经 tags/导出可核 → 至少各出现一次歧义与一次失败且被正确报告；
2. **旧配方回归**：无 `target` 步骤行为逐位不变(补断言)；
3. **确定性断言**：同 seed + 同检测配置 → 解析区间逐位一致(含跨基源场景)；
4. **截断条款确认**：P1 已完整在库，若 C 超限可截断，交接说明必须写清 target schema 与 matcher 接口现状——评估文档已有此条，保留。
## 四 · 两句战略提醒
1. **匹配器不要镀金**：C+D 的产出要喂给“坐标 vs 锚定迁移对照实验”(GPT P4,已排下一阶段)——那是 P2 价值的证伪实验。匹配器做到“可解释、可复现、失败显式”即可，精度调优等实验数据说话。
2. **主场景不忘**：走查要求里已有缺类重建场景一次(继承自任务书)，C 的旗舰演示(移植落点锚定)正是构造 F 类的机制雏形——走查记录按“将来可进论文”的标准留档。
## 五 · 一句收口
阶段 A/B 的执行比任务书更好(适配层路线 + 旧选中清除 + fingerprint 隔离都是超出要求的正确决策)，可以进 C——先花 30 分钟补检测器边界单测，把 D1–D6 六个决策写进任务书附录，然后放行：**C 的成败不在写了多少代码，而在 D1(旗舰演示的行为定义)和 D4(tags 不延后)这两条是否守住**。
